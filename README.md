# שיבוץ מדריכים – נוער שוחר מדע

אתר לשיבוץ מדריכים לימי עיון, קורסים, הרצאות ומופעי קסמים. האתר קורא את שני הקבצים שכבר יש לכם, מציג רק את מה שצריך לשבץ, ומפיק קובץ Word באותו מבנה כמו קובץ "משימות".

## איך עובדים עם זה

1. **קבצים** – גוררים את רשימת המדריכים (Excel, "נוער שוחר מדע - שיבוץ מדריכים") ואת קובץ הלו"ז (PDF, "קובץ לוז תשפ״ז" או כל שנה אחרת).
2. **מדריכים** – בודקים שהאתר הבין נכון מי מדריך/ה, מי קוסם/ת ומי מרצה, ואת אילוצי הזמינות (נקראים מעמודת "הערות"). מתקנים בלחיצה; התיקונים נשמרים גם כשמייבאים את הקובץ שוב.
3. **שיבוץ** – כל יום עיון/קורס מופיע ככרטיס, עם המשבצות שלו (הדרכה, הרצאה, מופע קסמים) והעמדות הפתוחות. לחיצה על עמדה פותחת רשימת מועמדים מסודרת:
   - קודם מי שמתאים/ה לתפקיד, פנוי/ה באותו יום ושעה ולא משובץ/ת במקביל;
   - בתוך זה – מי ששובצו הכי מעט החודש, ומי שעובדים הרבה עם בן/בת הזוג שכבר בקבוצה;
   - בנפרד: עם הסתייגות (שעות חלקיות, יום לא מועדף, הדרכת בטיחות חסרה), לא זמינים, ובלי התפקיד.
   - "שיבוץ אוטומטי של החסרים" ממלא את כל העמדות הפתוחות לפי אותם כללים (בכחול), ואפשר לבטל.
4. **ייצוא** – בוחרים חודש וחלקים (שובץ / לא שובץ / מדריכים שעוד לא שובצו / קורסים / הדרכות שבוצעו), מוסיפים "פערים לטיפול" ו"משימות", ומורידים Word או מעתיקים טקסט.

## כשהלו"ז מתעדכן (גם כל יום)

מעלים את הקובץ החדש בכפתור "עדכון לו"ז" בלשונית השיבוץ (אפשר אותו שם קובץ כל פעם). האתר משווה לגרסה הקודמת:

- **השיבוצים שלך נשמרים**, גם אם השעות של המשבצת השתנו (והמדריך/ה נבדק/ת מחדש מול השעות החדשות).
- **אם בלו"ז נכתב שם אחר** במקום שבו שיבצת מישהו - הלו"ז קובע, וזה מופיע ברשימת השינויים.
- **שם שנמחק מהלו"ז** - העמדה חוזרת להיות פתוחה.
- **יום עיון שהוזז לתאריך אחר** - עובר עם השיבוצים, עם תזכורת לבדוק שהמשובצים פנויים בתאריך החדש.
- **אירוע שנעלם מהלו"ז** ומישהו היה משובץ אליו - נשאר בלוח עם סימון, כדי שלא יישכח מישהו לעדכן.
- **אירועים חדשים** מסומנים "חדש".

בראש הלוח מופיעה רשימת "מה השתנה בעדכון הלו"ז", עם קישור לכל אירוע ואפשרות להציג רק את מה שהשתנה.

## כמה מכשירים, בלי מסד נתונים

כל מכשיר שומר את הנתונים אצלו (בדפדפן). כדי לעבוד ממחשב, מטלפון וממחשב נוסף יש שלוש דרכים, מהפשוטה לאוטומטית:

1. **הקישור ב-claude.ai** – שם הנתונים כבר נשמרים בחשבון, ומסונכרנים בכל מכשיר שמחובר אליו. אין מה להגדיר.
2. **העברה בקובץ** (לשונית "קבצים" ← "שליחה למכשיר אחר") – בטלפון נפתח תפריט השיתוף (WhatsApp לעצמכם, מייל, AirDrop, שמירה בקבצים), במחשב הקובץ יורד. במכשיר השני: "קבלה ממכשיר אחר". **הקובץ מתמזג ולא דורס**: בכל עמדה נשאר השיבוץ האחרון שנעשה, באיזה מכשיר שלא יהיה, ומה שנעשה רק במכשיר אחד נשמר. אם קיבלתם בטעות – "ביטול".
3. **סנכרון אוטומטי דרך GitHub** – הגדרה של פעם אחת, ומאז כל שינוי עובר לבד תוך שניות:
   1. יוצרים ריפו **פרטי** חדש (למשל `shibutz-data`).
   2. יוצרים [טוקן fine-grained](https://github.com/settings/personal-access-tokens/new): Repository access ← Only select repositories ← הריפו החדש; Permissions ← Contents: Read and write.
   3. באתר: "קבצים" ← "סנכרון אוטומטי דרך GitHub", מדביקים את שם הריפו והטוקן.
   4. במכשיר הבא: "חיבור מכשיר נוסף" מציג קוד QR – סורקים אותו בטלפון, או שולחים לעצמכם את הקישור.

   הנתונים נשמרים כקובץ `shibutz.json` בריפו, ו-GitHub שומר כל גרסה שלו (אפשר לחזור לגרסה קודמת מההיסטוריה). האתר מסרב לריפו ציבורי, כי בקובץ יש את פרטי המדריכים. הטוקן נשמר רק בדפדפן של המכשיר; בקישור החיבור יש את הטוקן, אז שולחים אותו רק לעצמכם. בלי אינטרנט ממשיכים לעבוד כרגיל, והשינויים נשלחים כשהחיבור חוזר.

איך המיזוג עובד: כל שינוי (שיבוץ, ניקוי עמדה, הערה, עריכת מדריך, משבצת) נשמר עם השעה שבה נעשה. כשנפגשים שני עותקים, הלו"ז שיובא מאוחר יותר קובע את מבנה האירועים, ועליו בכל עמדה נבחר הערך האחרון משני הצדדים. מחיקה של אירוע ידני או משבצת נשמרת כמחיקה, כדי שעותק ישן לא יחזיר אותם. העדפות התצוגה (סינון, חודש) נשארות לכל מכשיר בנפרד.

**באייפון** כדאי להוסיף את האתר למסך הבית (שיתוף ← הוספה למסך הבית): הוא נפתח כמו אפליקציה, ו-Safari לא ימחק את הנתונים של אתר שלא נפתח כמה ימים. לאתר שבמסך הבית יש אחסון נפרד מ-Safari, אז מעבירים אליו את הנתונים פעם אחת (בקובץ או בסנכרון).

## מה נחשב רלוונטי

- **ימי עיון וקורסים** (כולל סביון, גלילאו, אורט נופים וכו'). תוכניות ספיר/שוהם/ענבר, מפגשי היערכות וכדומה מוסתרים (אפשר להציג אותם ב"הצג מוסתרים").
- בכל אירוע: **הדרכות** (מעבדות, ניסויים, קורסים – בדרך כלל זוג מדריכים לכל קבוצה), **הרצאות** ו**מופעי קסמים**.
- סינון לפי תחום: ברירת המחדל היא כימיה + כללי. ביולוגיה, מחשבים ואחר כבויים וניתן להדליק אותם.

## הרצה

אתר סטטי, בלי שרת ובלי התקנה. הנתונים נשמרים בדפדפן (או בחשבון claude.ai כשהאתר פתוח שם); להעברה בין מכשירים ראו למעלה.

- **GitHub Pages**: Settings → Pages → Source: "Deploy from a branch" → בוחרים את הענף ואת התיקייה `/ (root)` → Save. אחרי דקה-שתיים האתר עולה בכתובת `https://<שם-המשתמש>.github.io/instructor-scheduling/`.
  - ב-GitHub החינמי, Pages עובד רק ל-repo ציבורי (ל-repo פרטי צריך GitHub Pro). אין בקוד נתונים אישיים: הקבצים שמייבאים נשארים בדפדפן של מי שמשתמש באתר ולא עולים ל-GitHub.
- **מקומית**: `npm start` (או `python3 -m http.server 8000`) ואז http://localhost:8000. פתיחה ישירה של `index.html` מהקובץ לא תעבוד, כי הדפדפן חוסם מודולים מ-`file://`.

```
index.html            מבנה הדף
css/style.css         עיצוב
js/app.js             ממשק: לשוניות, כרטיסים, בחירת מדריכים, עורכים
js/pdf-grid.js        קריאת ה-PDF (pdf.js): תאים, תאריכים וצבעים לפי מבנה הלו"ז השבועי
js/schedule-parser.js מטקסט תא לאירוע: סוג, תחום, משבצות, קבוצות ועמדות
js/roster.js          קובץ המדריכים: תפקידים, בטיחות, ואילוצי זמינות מטקסט חופשי
js/names.js           השוואת שמות בעברית (היבה/היבא, בוצ'קו/בוצקו, שם אמצעי)
js/scheduling.js      מיזוג ייבוא חוזר, התנגשויות, דירוג מועמדים, שיבוץ אוטומטי
js/export.js          מסמך הייצוא (Word / טקסט / תצוגה)
js/storage.js         שמירה (localStorage או claude.ai) והורדת קבצים
js/sync.js            חותמות זמן לשינויים ומיזוג של שני עותקים (קובץ או GitHub)
js/github-sync.js     קריאה וכתיבה של קובץ הנתונים בריפו פרטי (GitHub Contents API)
js/demo.js            נתוני הדוגמה (שמות מומצאים)
vendor/               pdf.js 4.10.38 בסיומת .js (בקובץ ה-worker תווי בקרה בתוך מחרוזות הוחלפו ב-\xNN, אותה משמעות)
```

בדיקות: `npm test` (Node 20 ומעלה, בלי תלויות).

ספריות: pdf.js (בתיקיית vendor), ‏SheetJS, ‏docx ו-qrcode-generator נטענות מ-CDN רק כשצריך אותן.
